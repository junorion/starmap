# Starmap AR 모드

안드로이드 앱에서 후면 카메라로 밤하늘을 비추면, 폰이 향한 방향에 맞춰 별자리 선과 이름을 카메라 영상 위에 겹쳐 보여주는 작업 단위입니다. [기본 하늘지도 스펙](../starmap-sky-chart/spec.md)의 "AR 모드(웹에서는 안내만)"를 앱에서 실제 기능으로 바꾸고, [안드로이드 앱 스펙](../android-app/spec.md)의 래퍼 위에서 동작합니다.

## 사용자에게 보이는 결과

1. 앱에서 오른쪽 아래 AR 모드 버튼을 누르면 카메라 권한을 묻고, 허용하면 후면 카메라 영상이 화면 전체에 나온다.
2. 폰을 하늘로 들면 그 방향에 있는 별자리 선·이름·밝은 별이 영상 위에 겹쳐 그려지고, 폰을 움직이면 실제 하늘에 붙어 있는 것처럼 따라 움직인다. 지평선과 N/E/S/W 가 함께 보여 어디로 돌려야 할지 알 수 있다.
3. 겹친 그림이 실제 별과 옆으로 어긋나 보이면, 화면을 좌우로 끌어 맞출 수 있다.
4. 별자리를 누르면 하늘지도와 같은 설명 팝업이 뜬다. 닫기나 뒤로 가기로 하늘지도에 돌아온다.

## 범위

**포함**
- 진입과 종료
  - 앱 안에서 AR 모드 버튼을 누르면 AR 화면으로 들어간다. 이때 처음으로 카메라 권한을 묻는다(안드로이드 권한 대화상자).
  - 카메라 권한을 거부하면 AR 화면으로 들어가지 않고, 하늘지도 위에 "카메라 권한이 있어야 AR 모드를 쓸 수 있다"는 안내 창을 띄운다. 안내 창에는 "확인" 단추가 있고, 다시 버튼을 누르면 권한을 다시 묻는다(안드로이드가 더 묻지 않는 상태면 앱 설정에서 켜라고 안내한다).
  - AR 화면에는 왼쪽 위에 닫기 버튼이 있다. 닫기나 안드로이드 뒤로 가기를 누르면 카메라를 끄고 하늘지도로 돌아온다. 열려 있던 별자리 팝업이 있으면 뒤로 가기는 팝업부터 닫는다.
  - 브라우저(앱 밖)에서는 지금처럼 안내 창만 뜬다. 문구는 "AR 모드는 Starmap 안드로이드 앱에서 쓸 수 있습니다"로 바꾼다. 브라우저에서는 카메라 권한을 묻지 않는다.
- AR 화면
  - 후면 카메라 영상이 화면 전체를 채운다(비율을 지키며 잘라서 채운다). 영상은 저장하거나 어디로도 보내지 않는다.
  - 영상 위에 지금 하늘지도와 같은 데이터와 계산으로 그린다: 별자리 선과 이름, 4등급까지의 밝은 별(카메라 영상 위라 6등급까지는 너무 빽빽하다), 지평선, 지평선 위의 N/E/S/W.
  - 지평선 아래 방향(땅 쪽)을 비추면 그쪽 하늘도 하늘지도처럼 밝기 70% 로 어둡게 그린다.
  - 옵션 창의 "지표별 추가"가 켜져 있으면 지표별 도형도 같은 모양으로 그린다. 작은 별자리 숨김(화면에서 60px 미만)은 하늘지도와 같은 규칙을 따른다.
  - 폰의 방향(나침반 방위와 기울기)을 따라 그림이 실시간으로 움직인다. 세로·가로 화면 모두에서 맞게 그린다.
  - 그림의 크기는 그 기기 후면 카메라의 실제 화각에 맞춘다. 그래서 겹친 별자리의 크기가 영상 속 실제 별 간격과 같다.
  - 화면 위쪽에 위치·시각 줄을 하늘지도와 같은 모양으로 둔다.
- 어긋남 맞추기(수동 보정)
  - 화면을 좌우로 끌면 겹친 그림 전체가 방위 방향으로 돌아간다(끈 거리만큼 화면에서 같은 거리를 따라온다). 위아래로 끄는 것은 무시한다. 기울기는 가속도 센서로 정확하지만, 방위는 나침반이라 흔히 10–20° 틀리기 때문이다.
  - 맞춘 보정값은 AR 화면을 닫았다 다시 열어도 앱을 끄기 전까지 유지한다. 보정이 0이 아니면 화면에 "보정 ±N°"와 "보정 초기화" 버튼이 보인다.
  - 짧게 누르는 것(4px 이하 이동)은 끌기가 아니라 별자리 선택으로 본다.
- 별자리 선택
  - 화면을 누른 지점에서 20px 이내의 별자리 선을 선택하는 규칙은 하늘지도와 같다. 선택한 별자리는 노란 강조로 바뀌고 하늘지도와 같은 팝업이 뜬다.
  - AR 화면에서 고른 별자리는 하늘지도로 돌아가도 선택된 채 남는다(같은 선택 상태를 쓴다).
- 쓸 수 없을 때
  - 기기에 방향 센서가 없거나 방향 값을 받지 못하면, 카메라 영상 위에 "이 기기에서는 방향 센서를 쓸 수 없어 별자리를 겹쳐 그릴 수 없습니다"를 보여 주고 닫기만 할 수 있다.
  - 방향 값이 3초 넘게 들어오지 않으면 같은 안내를 띄운다.

**이번에 하지 않을 것:** 카메라 영상 속 별 자동 인식, 찾기 결과로 안내하는 화살표, 사진·영상 저장, 확대(줌), 돌리기 모드, 위아래 보정, 보정값의 영구 저장, iOS

## 인수 기준

- 브라우저에서 AR 모드 버튼을 누르면 "AR 모드는 Starmap 안드로이드 앱에서 쓸 수 있습니다" 안내가 뜨고, 카메라 권한을 묻지 않는다.
- 앱에서 AR 모드 버튼을 누르면 카메라 권한을 묻고, 거부하면 하늘지도에 안내 창이 뜨며 지도는 그대로다.
- (실기기) 권한을 허용하면 후면 카메라 영상이 화면 전체에 나오고, 폰을 하늘로 들면 별자리 선과 이름이 겹쳐 보인다.
- (실기기) 폰을 좌우·위아래로 돌리면 겹친 그림이 반대로 움직여 하늘에 붙어 있는 것처럼 보이고, 세로·가로 화면 모두에서 그렇다.
- (실기기) 폰을 북쪽 지평선으로 향하면 화면 가운데 근처에 "N" 이 보인다(보정 전 나침반 오차만큼 어긋날 수 있다).
- (실기기) 맑은 밤에 밝은 별이 있는 쪽을 비추고 화면을 좌우로 끌면 겹친 그림이 따라 돌아, 실제 별과 겹치게 맞출 수 있다. "보정 초기화"를 누르면 처음 상태로 돌아간다.
- 방향 값을 화면 좌표로 바꾸는 계산은 테스트로 고정한다: 폰을 정북·고도 0° 로 향했을 때 방위 0° 지점이 화면 가운데, 고도가 화각의 절반인 점이 화면 위 끝에 오고, 방위 보정 +10° 를 주면 정북에서 10° 동쪽(방위 10°)인 점이 가운데로 온다. 세로·가로 화면 회전에서도 같은 결과다.
- 별자리 선 20px 이내를 누르면 그 별자리가 선택되어 팝업이 뜨고, 4px 넘게 끌면 선택하지 않고 보정만 바뀐다.
- AR 화면에서 닫기나 뒤로 가기를 누르면 카메라가 꺼지고(카메라 사용 표시가 사라짐) 하늘지도로 돌아온다. 팝업이 열려 있으면 뒤로 가기는 팝업만 닫는다.
- 방향 값을 3초 동안 받지 못하면 "방향 센서를 쓸 수 없다"는 안내가 뜬다.
- 기존 하늘지도의 테스트가 모두 통과한다.

## 확정된 제약과 근거

- **첫 버전 범위는 겹쳐 보기, 방향 단서, 별자리 탭, 좌우 끌어서 보정이다.** 사용자가 확정했다(2026-10-29). 보정을 넣은 이유는 나침반 오차(흔히 10–20°)만으로도 별자리가 자기 크기만큼 밀려 보여, 보정 없이는 AR 의 쓸모가 떨어지기 때문이다.
- **제품 경계는 유지한다:** 서비스는 카메라 영상 속 별을 알아보지 않는다. 폰이 향한 방향으로 계산한 위치에 그릴 뿐이고, 맞는지의 판단과 보정은 사용자의 몫이다([PRODUCT.md](../../../PRODUCT.md)). PRODUCT.md 의 "AR 은 나중 확장" 문장은 이번 결정에 맞춰 `define-product` 로 고쳤다(2026-10-29).
- **카메라와 방향은 웹 표준 API 로, 카메라 화각만 안드로이드가 알려준다.** 근거: MDN browser-compat-data 8.1.7 에서 Android WebView 는 `getUserMedia`(53+), `AbsoluteOrientationSensor`(67+), `deviceorientationabsolute`(50+)를 지원하지만 카메라 화각을 알려주는 웹 API 는 없다. 화각을 모르면 겹친 그림의 크기가 실제 하늘과 어긋난다. 웹에 없는 것만 안드로이드가 메운다는 래퍼 원칙과도 맞다. 이 판단을 다시 볼 때: WebView 가 화각을 웹에 알려주게 되거나, 실기기에서 웹 방향 값이 쓸 수 없을 만큼 흔들릴 때.
- **앱인지는 안드로이드가 붙인 화각 연결이 있는지로 안다.** 지난번처럼 user agent 표시 같은 별도 판별을 두지 않는다.
- **하늘 계산과 데이터는 하늘지도와 같은 것을 쓴다**(astronomy-engine, d3-celestial 데이터, 지금 위치·시각). AR 은 같은 하늘을 다른 투영(카메라 시야)으로 그릴 뿐이다.
- **확인 기기는 갤럭시 탭 A8(SM-X200) 태블릿이다.** 제3자 사양표 세 곳은 가속도·자이로·지자기 센서와 8MP 후면 카메라가 있다고 적었지만 삼성 공식 사양으로는 확인하지 못했다. 태블릿에서 확인할 수 없는 항목은 확인 가능한 범위까지만 보고, 시험폰을 구한 뒤 확인한다(사용자 결정). 시험폰 갤럭시 A5 는 Family Link 때문에 지금은 설치할 수 없다.

## 가정 (에이전트가 정한 값, 바꿀 수 있음)

- AR 화면의 밝은 별 기준은 4등급까지다.
- 보정은 좌우(방위)만 한다. 위아래로 끄는 것은 무시한다.
- 보정값은 앱을 끄기 전까지만 기억한다.
- 방향 값이 3초 넘게 없으면 센서를 쓸 수 없다고 본다.
- 브라우저 안내 문구는 "AR 모드는 Starmap 안드로이드 앱에서 쓸 수 있습니다"로 바꾼다.
- 닫기 버튼은 왼쪽 위, 보정 표시와 "보정 초기화"는 화면 아래 가운데에 둔다. 위치·시각 줄은 하늘지도와 같은 위치다.
- 방향은 `AbsoluteOrientationSensor` 를 먼저 쓰고, 안 되면 `deviceorientationabsolute` 를 쓴다. 폰을 하늘 높이(천정 근처) 들 때 각도 세 개(알파·베타·감마)로는 값이 튀기 쉬워서, 회전을 한 덩어리(쿼터니언)로 주는 쪽을 먼저 쓴다.
- 화각을 받지 못하면 세로 화면 기준 가로 화각 60° 를 쓴다.

## 미뤄 둔 사항

- 찾기 결과로 안내하는 화살표(찾은 별자리가 화면 밖이면 그쪽을 가리킴)는 겹쳐 보기와 보정이 실제 하늘에서 맞는지 확인한 뒤 정한다.
- 나침반 보정 안내(8자 그리기 등)를 띄울지는 실기기에서 오차를 본 뒤 정한다.
- 보정값을 영구히 저장할지는 정하지 않았다.

## 남은 위험

- **나침반 정확도:** 실내, 자석 케이스, 전자기기 근처에서는 방위가 수십 도 틀릴 수 있다. 보정으로 메울 수 있지만, 폰을 크게 돌리면 다시 틀어질 수 있다.
- **태블릿 실기기 확인:** SM-X200 의 센서를 공식 사양으로 확인하지 못했다. 센서가 없으면 겹쳐 보기와 보정은 확인할 수 없고, 권한·카메라·안내 화면까지만 확인된다.
- **밤 카메라 영상:** 저가 카메라는 밤하늘을 거의 검게 찍는다. 그래도 겹친 그림은 보이지만, 실제 별과 맞추는 보정은 밝은 별이 영상에 찍혀야 할 수 있다.
- **이 개발 환경:** 에뮬레이터와 센서가 없어서 방향 계산은 테스트로, 카메라·센서·권한은 실기기에서만 확인된다.
